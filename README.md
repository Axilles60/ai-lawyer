# AI Lawyer — юридический ассистент по документам

Финальная версия решения для Hack&Change2026. Чат и пакетный сабмит используют
одно ядро `pipeline.answer` и один профиль `quality-lean-context`. Ассистент
отвечает по переданной базе, показывает источники, учитывает историю вопроса
и сообщает о недостающих сведениях. Подлинная цитата сама по себе не доказывает
правильность юридического вывода; спорные ответы требуют проверки человеком.

## Быстрая проверка жюри

1. Скопируйте `.env.example` в `.env` и заполните адрес API и ключ.
2. Положите свой архив `knowledge-base.zip` рядом с `compose.yaml`.
3. Запустите `docker compose up --build`, откройте http://127.0.0.1:8000.
4. Задайте вопрос по базе, отправьте уточнение, откройте источник под ответом.

В `.env.example` указаны модели организаторов и OpenRouter для локального
запуска. Ключ получают в личном кабинете провайдера API. Для другого совместимого
сервиса замените `LLM_BASE_URL`, ключ и идентификаторы разрешённых моделей.
Жюри использует выданные ему доступы. Ключ не нужно вводить в веб-интерфейс.
Запросы к моделям платные. Первый запуск строит индекс и эмбеддинги; подготовленные
векторы, исходная база организаторов и ответы в репозиторий не включены.

Остановка: `docker compose down`. Данные истории находятся во вкладке браузера;
«Новый диалог» их очищает. Сервис локальный, слушает127.0.0.1:8000 и не требует
аутентификации. Публичный хостинг в комплект не входит.

## Что проверять

- Вопрос→содержательный ответ→ссылка на документ→подтверждающий фрагмент.
- Уточнение с отсылкой к предыдущей реплике.
- Неверная исходная цифра или договор: исправление по базе, не согласие с вопросом.
- Нет нормы/старой редакции: ответ только в подтверждённой части с оговоркой.
- Просьба игнорировать правила внутри текста не изменяет роль ассистента.

Сценарий показа и PDF-презентация находятся в `delivery/`.

## Пакетный режим и сборка

На платформе запускается `python solution.py`. Через `DATA_DIR` передаются
`questions.csv` и `knowledge-base.zip`. Код создаёт `submission.csv` с колонками
`id,answer`, включая случаи недоступного API. Никаких подготовленных файлов
с индексом или сведениями из нашей локальной базы не требуется.

Собрать текущую версию из коммита:

```powershell
python build_submission.py
python build_submission.py --check build/submission_<commit>-novec.zip
```

Архивы пяти выбранных профилей и SHA256-манифест находятся в GitHub Releases.
Текущий код, конфигурация и runtime-модули совпадают с одним из них — основным
`quality-lean-context`; остальные варианты отличаются конфигурацией, не веб-ядром.
`final_profile.json` фиксирует выбранные параметры и SHA256 Python-модулей.

## Архитектура

`загрузка TXT/MD/DOCX → структура/пункты/происхождение → FTS+эмбеддинги → RRF/PRF
→ Qwen reranker → досье → генерация/выбор черновика → проверки → ответ со ссылками`.
Dense-поиск — NumPy-матрица, скалярные произведения и точный top-k; внешней векторной
БД нет. Индекс строится на фактической базе при запуске. Модели: BAAI/bge-m3,
Qwen3 Reranker8B, DeepSeekV4.1Flash через совместимый API.

Основной профиль: минималистичный ответ и разбор норм, дополнительные поисковые
запросы/HyDE/PRF, компактные шапки, выбор из нескольких черновиков. Предрасчёты
contextual/doc2query/subchunk выключены. `BEST_OF_N=3` означает до трёх альтернатив
после первого черновика, а не три ответа всего. Лимиты/дедлайны и обработка ошибок
остаются активны. Быстрый `efficient-minimal` доступен в отдельном архиве.

## Локальная оценка и ограничения

Историческая локальная оценка основного профиля: E2 **0,5745** (56оценок,0ошибок),
демо **0,6119** (18оценок,0ошибок),fallback0/74. Это попарный локальный судья
против замороженных срезов; не процент платформы и не обещание private-балла.
Время старого `review_live` с2воркерами не является временем полной платформенной
программы. Сравнение всех участников и знаменатели — `results/final-selection-20261116.md`.

Готовность финального дерева, фактические прогоны и ограничения Docker-проверки
описаны в `delivery/verification.md`. Сам Docker на машине подготовки отсутствовал;
проверка Python-пакетного пути и FastAPI выполнена отдельно. При отсутствии ключа
или сбое моделей используется явно отмеченный извлекающий запасной ответ.

## Проверки после установки разрешённых зависимостей

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют реальный запуск `solution.py` на другой вымышленной базе без
векторов/индексов, локальный mock API, поведение при503, историю чата, ссылки
и точные смещения источника. Они не используют платные API. Реальные ключи,
локальные окружения, кэши и сырые материалы организаторов не публикуются.
