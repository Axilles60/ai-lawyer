# AI Lawyer — юридический ассистент по документам

Ассистент отвечает по переданной базе, показывает положения документов и сообщает,
каких данных не хватает. Веб-чат и пакетный режим используют одно ядро
`pipeline.answer`. Основной профиль — `quality-lean-context`.

## Запуск и проверка

Нужен Docker с Compose. Для полноценной генерации нужен доступ к API моделей.

1. Скопируйте `.env.example` в `.env`, заполните `LLM_BASE_URL` и `LLM_API_KEY`.
2. Положите выданный архив `knowledge-base.zip` рядом с `compose.yaml`.
3. Запустите одну команду:

```sh
docker compose up --build
```

Откройте **http://127.0.0.1:8000**. Первый запуск устанавливает закреплённые
зависимости внутри образа и строит индекс по вашей базе. Подготовленных векторов
и самой базы в репозитории нет. Если файл базы отсутствует, запуск завершается
ошибкой подключения файла, не создавая каталог вместо него.

Для проверки задайте вопрос по договору из списка документов, дождитесь ответа,
откройте ссылку под ним и проверьте выделенное положение. Затем отправьте уточнение.
Проверьте также вопрос без ответа в базе и непрофильный запрос. «Новый диалог»
очищает историю. Полный сценарий: [delivery/demo-script.md](delivery/demo-script.md).

Остановка: `docker compose down`.

## API и окружение

В `.env.example` указан OpenRouter. Ключ получают в личном кабинете провайдера;
для другого OpenAI-совместимого сервиса замените адрес и идентификаторы разрешённых
моделей. Ключ вводится только в локальный `.env`, в веб-форме он не требуется.
На платформе адрес, ключ и модель подставляются организаторами автоматически.

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | Адрес совместимого API, локальный пример: `https://openrouter.ai/api/v1` |
| `LLM_API_KEY` | Ключ доступа, вызовы могут быть платными |
| `LLM_MODEL` | `deepseek/deepseek-v4.1-flash` |
| `EMB_MODEL` | `baai/bge-m3` |
| `RERANKER_MODEL` | `qwen/qwen3-reranker-8b` |
| `MAX_WORKERS` | Параллелизм пакетного запуска, по умолчанию 8 |
| `DATA_DIR` | Каталог входных файлов пакетного запуска, по умолчанию `data` |
| `KB_PATH` | Путь базы для веба; Compose задаёт `/data/knowledge-base.zip` |

Все зависимости закреплены в `requirements.txt` и входят в разрешённый набор.
Сервис публикуется только на `127.0.0.1:8000`, работает без аутентификации и
предназначен для локальной демонстрации. Публичный хостинг не требуется для сдачи.

## Архитектура

`TXT/MD/DOCX → структура и происхождение чанков → FTS + BGE-M3 → RRF/PRF
→ Qwen reranker → досье → DeepSeek и выбор черновика → проверки → ответ и источники`.

Dense-поиск использует NumPy-матрицу, скалярные произведения и точный top-k.
Внешний сервер векторной БД не нужен. Фрагменты перекрываются; у каждого есть
документ, файл, структурный путь и строки нормализованного исходника. Компактные
заголовки, дополнительные поисковые запросы и PRF включены. `BEST_OF_N=3`
означает до трёх альтернатив после первого черновика за цикл. Готовые contextual,
doc2query и subchunk-представления выключены. Подробный контракт — `SPEC.md`.

## Версия и сабмиты

Ядро и настройки GitHub побайтно соответствуют **`submission_bd82280-novec.zip`**.
В финальной доработке улучшены веб, контейнер и инструкции; 24 Python-модуля
этого бот-архива и `config.py` не изменены. `final_profile.json` фиксирует хэши.
Зависимости бот-архива — подмножество тех же закреплённых версий; веб дополнительно
использует FastAPI и Uvicorn.

Пять вариантов, полный исходный ZIP и PDF — в [актуальном выпуске](https://github.com/Axilles60/ai-lawyer/releases/latest).
Для финальной сдачи загрузите **`ai-lawyer-final.zip` либо `presentation.pdf`**.
Пять `submission_*.zip` предназначены для отдельной автоматической оценки.

На платформе точка входа — `python solution.py`; входы `DATA_DIR/questions.csv`
и `DATA_DIR/knowledge-base.zip`. Выход в рабочем каталоге — `submission.csv`
с колонками `id,answer` и непустым ответом для каждого ID.

Сборка текущего кода: `python build_submission.py`. Проверка готового архива:
`python build_submission.py --check build/submission_bd82280-novec.zip`.
Сборка не вызывает API и включает только корневые runtime-модули и зависимости.

## Ограничения

Цитата доказывает наличие текста, а не правильность вывода. Юридически значимые
ответы требуют проверки человеком. При недоступности API используется явно
отмеченный извлекающий запасной ответ. История хранится во вкладке и исчезает
при перезагрузке. Источники показаны под ответом; привязка каждой фразы к ссылке
не гарантируется. Неизвестное число private-вопросов и другая скорость API могут
повлиять на время и запасные ответы.

Локальный попарный Score E2 — 0,5249 (55 оценок, 1 ошибка судьи), демо — 0,5392
(18 оценок). Это шкала 0–1, не процент правильных ответов и не платформенные баллы.
Исторические сравнения: `results/final-selection-20261116.md`.
Тесты Docker с имитацией моделей и живой API-проверкой проведены отдельно.
Факт загрузки финального PDF/ZIP на платформу подтверждает участник.
