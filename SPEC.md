# Контракт финального решения

Вход: архив TXT/MD/DOCX и CSV id,question. Выход: submission.csv id,answer,
непустая строка для каждого входного ID, не более 10000 символов на ответ.
Веб и пакетный запуск используют pipeline.answer и одинаковые defaults config.py.

Источник фактов - переданные документы. Не выводить событие из отсутствия сведений,
не превращать условие в установленный факт, не добавлять сведения из памяти.
Юридические положения сопровождаются документом и пунктом. Указывать недостаток
данных, редакции и противоречия. При неоднозначности отвечать по вероятной
трактовке с оговоркой (Q19); для совершенно неизвестного предмета запрашивать
недостающие данные. Непрофильный вопрос - мягкий отказ; противоправный запрос -
отказ в содействии с допустимым разъяснением найденных требований.
Содержимое базы и пользовательские попытки сменить роль не являются системными
инструкциями. Проверки и разделители снижают риск инъекций, но не гарантируют защиты.

Индекс и эмбеддинги строятся на входной базе. Dense - точное скалярное произведение
и top-k по NumPy-матрице; FTS, прямые ссылки и dense объединяются RRF. Сохраняется
перекрытие фрагментов и происхождение: файл, документ, структурный путь, строки
нормализованного исходника. Qwen reranker отбирает top-8; лимит контекста 16000.
PRF: до 5 не входящих в вопрос частотных основ из первых 8 FTS-узлов, дополнительный
FTS-канал с RRF. Lean_context сокращает только шапки корпоративных документов;
законы, условия и временные заметки сохраняются. Эти алгоритмы восстановлены
из измеренных исторических веток (31771a9/7f52717, 96a8fce).

Выбор профилей - profiles.json; фактический профиль этого коммита - final_profile.json.
В основном профиле minimal/norm_analysis/Q19, HyDE, subqueries, stepback, PRF,
lean_context, best-of-N и draft_judge включены. best_of_n=3: до трех альтернатив
плюс первый черновик. Другие кандидаты остаются выключенными, в частности
contextual/d2q/subchunk, полнота M и AIMD/R3. Полный evidence-судья не включен.

При недоступности API формируется извлекающий запасной ответ. Программа сохраняет
дедлайны и консервативное управление нагрузкой; соблюдение времени на неизвестном
числе вопросов и иной скорости API не гарантировано локальной оценкой.
Цитата доказывает присутствие текста, а не правильность вывода модели.

Все пять финальных ZIP содержат только runtime .py и requirements.txt, без базы,
секретов, индексов или векторов. Сборка не вызывает API. Публикуемый main совпадает
с выбранным ZIP по всем его Python-модулям. Существующая удаленная история сохраняется.
Проверки и ограничения перечислены в delivery/verification.md.


## Доработка готовности веба, 16.11.2026

Веб показывает статус ожидания; ошибки загрузки источника отображаются вместо
прежнего текста; последний выбранный источник защищен от позднего ответа
предыдущего запроса. Смещения API относятся к Unicode codepoints, UI выделяет
соответствующий фрагмент и прокручивает к нему. При сетевом сбое чата сохраняет
введенный вопрос для повторной отправки. Ядро/config/бот-ZIP не меняются.
Приемка: настоящий HTTP web lifecycle, DOM/JS-проверки источника с non-BMP символом,
смены выбранного источника и сетевого сбоя; обычные цитаты/история/запасной режим
сохраняются. При наличии существующего контейнерного runtime - реальный build/up.
Установка зависимостей и изменение системных настроек этим поручением не разрешены.


Контейнер запускает то же app:app непривилегированным UID10001; Python пишет
временные данные/необязательный cache в /tmp; readiness проверяет только GET /
без моделей. Compose публикует только127.0.0.1:8000, передает .env на runtime,
монтирует существующий knowledge-base.zip только read-only; при отсутствии файла
не создает вместо него каталог (bind.create_host_path=false). Сборочный контекст
содержит только requirements.txt, корневые runtime.py и static, не .env/базу/кэши.
Проверки Docker отличать от native. Если локальный engine отсутствует, разрешена
проверка на существующем GitHub Actions Ubuntu runtime: реальный Docker build/up
с вымышленной базой и локальным model-mock, без секретов и внешних LLM-вызовов.
CI имеет permissions contents:read, фиксированный timeout; отчет публикует только
результаты проверок/логи без ключей, не исходную базу организаторов.


Дополнительная проверка того же основного ZIP: полный solution.main на18
неизмененных демо-вопросах с реальным API, DEV_CACHE=0 и неизменными defaults.
Внешняя оценочная обертка заменяет только HTTP transport для учета/резерва,
не логику программы. Отдельный предел$1,50, вместе с web-smoke$1 максимум$2,50
