# Сценарий демонстрации

Дата подготовки: 16.11.2026. Репозиторий:
https://github.com/Axilles60/ai-lawyer.

## Подготовка

1. Открыть README выбранного финального коммита. Сверить имя финального архива
   и хэши в manifest выпуска. Остальные четыре архива являются альтернативами.
2. Получить доступ к OpenAI-совместимому API моделей организаторов. Создать `.env`
   по `.env.example`, заполнить URL, ключ и идентификаторы моделей по README.
   Не показывать окно с ключом на защите и не добавлять `.env` в репозиторий.
3. Положить входной `knowledge-base.zip` рядом с `compose.yaml`. Запустить
   `docker compose up --build`. Первый запуск может скачивать образ и зависимости.
   Подготовка базы и генерация могут обращаться к платному API.
4. Открыть http://127.0.0.1:8000. Дождаться списка документов.

## Основной сценарий, 3–4 минуты

1. Задать конкретный вопрос по существующему входному документу. Не выбирать
   заранее заданный факт из кода: взять название документа из списка и условие
   из базы, которую использует жюри.
2. Показать прямой ответ и его оговорки. Открыть ссылку под ответом. Показать
   заголовок документа, номер положения и выделенный фрагмент.
3. Уточнить вопрос следующей репликой. Показать, что обрабатывается последняя
   реплика с учётом переданной истории, а не отдельный подготовленный ответ.
4. Задать вопрос, для которого в базе не хватает фактических данных. Проверить,
   что ассистент сохраняет подтверждённую часть и не подставляет неизвестные числа.
5. Задать непрофильный вопрос. Проверить мягкий отказ от ответа вне компетенции.
6. Нажать «Новый диалог». Убедиться, что история в интерфейсе очищена.

## Пакетный путь

Запустить `solution.py` с входом `DATA_DIR/questions.csv` и архивом базы по README.
Показать результат `submission.csv`: колонки `id,answer`, один непустой ответ на
каждый входной ID. Для чата и пакета используется общее ядро `pipeline.answer`.

## Резерв при недоступности API

Показать честно помеченный запасной ответ и переход к найденному положению.
Объяснить, что это демонстрация интерфейса и деградации, а не результат работы
генеративной модели. Скриншоты в презентации сняты именно в таком режиме:
API отключены, HTTP 200, один источник и подсвеченный фрагмент.

## Что объяснить экспертам

- Все поисковые представления строятся по входной базе во время запуска;
  предзагруженных векторов и индексов в финальных сабмитах нет.
- Модели генерации, эмбеддингов и реранкинга берутся из настроек окружения.
- Наличие цитаты не гарантирует правильности вывода. Условия и редакции остаются
  предметом содержательной проверки.
- Прототип не содержит аутентификации и рассчитан на одного пользователя.
