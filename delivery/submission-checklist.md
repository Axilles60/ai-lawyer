# Проверка финальной сдачи

Источники: кейс ПСБ, «Формат сдачи», страница 11; «Допуск», страница 14;
технический регламент ПСБ. Сдача: **PDF со ссылкой на репозиторий на первом
слайде либо ZIP с исходниками, документацией и PDF**. PPTX и публичный хостинг
не обязательны. Пять бот-сабмитов относятся к автоматическому этапу и не заменяют
финальные материалы.

## Три обязательных условия допуска

- [x] На платформе есть результат LLM-судьи **больше нуля**: для
  `submission_bd82280-novec.zip` пользователь подтвердил **37,601**, статус
  `success`, 16.11.2026 в 12:40 МСК, время **903,2 с**.
  Источник — сообщение пользователя, не самостоятельный запрос к платформе:
  [`results/platform-final-20261116.json`](../results/platform-final-20261116.json).
- [x] Веб-чат прошёл реальный браузерный сценарий с моделями: два запроса,
  **35,523 / 58,252 с**, оба без fallback, источники и история работают,
  видимая подсветка — **95 символов**. Дополнительно проверены недостающие
  сведения и отказ. Подробности — [`verification.md`](verification.md).
- [ ] **Осталось участнику:** загрузить финальный PDF или полный ZIP на платформу
  до дедлайна, сохранить подтверждение приёма и зафиксировать версию.
  Материалы подготовлены и опубликованы, но факт этой финальной загрузки
  не подтверждён. Успешный бот-сабмит не заменяет сдачу материалов.

## Состав и проверка комплекта

| Требование | Где находится | Проверка перед отправкой |
|---|---|---|
| Репозиторий и порядок проверки на первом слайде | `presentation.pdf` | Открыть PDF, проверить ссылки и читаемость |
| Проблема, пользователь, архитектура | PDF, README | Описание соответствует выбранному профилю |
| Сценарии, примеры ответов и отказов | PDF, `demo-script.md`, снимки | Резервные ответы явно помечены |
| Ограничения и развитие | PDF, README | Нет обещаний нулевых ошибок и неизвестного private-балла |
| Работающий код | Корень проекта | Пакетный и веб-путь используют общее ядро |
| Одна команда запуска | README, Dockerfile, compose.yaml, .dockerignore | Реальная Compose-сборка и запуск пройдены в GitHub Actions; включая отрицательные проверки, см. `verification.md` |
| Зафиксированные зависимости | `requirements.txt` | Версии фиксированы, установки внутри solution нет |
| Окружение без секретов | `.env.example` | Нет действующих ключей; описаны провайдер, модели и подключение |
| Та же модель в прототипе и сабмите | Настройки окружения, README | Сверить имена моделей с регламентом, не только наличие общего ядра |
| GitHub равен выбранному бот-архиву | `final_profile.json`, манифест | Python runtime-модули сравниваются побайтно, включая config.py |
| Нет предзагруженных векторов и индексов | Пять бот-архивов | Проверить содержимое ZIP; входная база и кэши не включены |
| Доступ жюри | GitHub | Для приватного репозитория дать доступ `hack-and-change-2026` |
| Фиксация после дедлайна | Коммит/тег и загруженный файл | Записать точный SHA версии, имя и SHA256 отправленного файла |

## Автоматический бот-сабмит

- [x] Выбран один основной архив `submission_bd82280-novec.zip`; четыре альтернативы явно названы альтернативами.
- [x] ZIP плоский, содержит `solution.py`, разрешённые модули и зависимости;
  не содержит `.env`, входных вопросов/базы, ответов, кэшей и готовых векторов.
- [x] Реальный холодный запуск выбранного ZIP на 18 демо-вопросах: 163,2 с,
  18 полных ответов, 0 fallback и 0 economy, 232 API-вызова. CSV: UTF-8, ровно `id,answer`, все входные ID по одному, непустой ответ
  не длиннее 10 000 символов, корректное CSV-экранирование.
- [x] Учтены лимиты: ZIP до 128 МБ, 8 CPU / 16 ГБ, полный прогон до 20 минут,
  не более пяти сабмитов в сутки, сброс в 00:00 МСК. Время локального судьи
  не является доказательством соблюдения платформенного лимита. Подтверждённая
  пользователем попытка завершилась за 903,2 с; это результат этой попытки,
  а не гарантия времени для любой новой базы.

## Что зафиксировать после отправки

Участник записывает имя файла, SHA256, коммит, время отправки, статус приёма,
ID попытки и результат платформы; отдельно — подтверждение финальной сдачи PDF/ZIP.
Секреты и содержимое `.env` к подтверждению не прикладываются. Фактические проверки
и оставшиеся ограничения — в `verification.md` и `final-readiness.md`.
